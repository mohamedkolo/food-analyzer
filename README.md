# NutraX

‏منصة تغذية إكلينيكية: بتولّد خطط غذائية أسبوعية، بتقرا ورق تحليل
الجسم (InBody)، وبتتابع العملاء من زيارة لزيارة. عربي/إنجليزي، والورقة
اللي بتطلع منها بتتطبع وتتسلّم للعميل.

Flask + Jinja + WeasyPrint · Postgres (Neon) في النشر، SQLite محلياً ·
٤٢ ملف بايثون · ٤١ ملف اختبار (~٧٤٠ اختبار).

---

## تشغيله محلياً

```bash
pip install -r requirements.txt

export SECRET_KEY=any-string
export ADMIN_PASSWORD=pw123456
export NUTRAX_DB=/tmp/nutrax.db        # ‏من غير DATABASE_URL بيشتغل SQLite

python3 app.py                          # http://127.0.0.1:5000
```

‏الجداول بتتعمل لوحدها أول تشغيل، ومعاها حساب أدمن.

### الاختبارات

```bash
python3 tests/run_all.py                # ‏الطقم كله
python3 tests/test_three_meals.py       # ‏ملف واحد
```

‏الرنر بيدّي لكل ملف قاعدة نضيفة، وبيقول كمان لو فيه اختبار **معرّف
ومااشتغلش** -- اختبار مش بيتنادى أسوأ من اختبار فاشل، لأن الفاشل
بيقولك.

### النشر

```
gunicorn app:app --bind 0.0.0.0:$PORT --timeout 120 --workers 1
```

## اللي لازم يتعرف قبل أي تعديل

‏الحاجات دي مش أسلوب -- كل واحدة فيهم **وقّعت حاجة فعلاً**، ومكتوب
جنبها في الكود ليه. واللي بياخد المشروع ده (إنسان أو ذكاء اصطناعي)
لازم يقراها قبل ما يغيّر:

1. **`/health` مابتلمسش قاعدة البيانات.** اتضاف لها فحص للقاعدة مرة،
   فالـping اللي كل ١٠ دقايق فضل يصحّي Neon ليل ونهار، والحصة الشهرية
   خلصت، والمشروع اتوقف والموقع وقع. الفحص بقى تحت الطلب:
   `/health?db=1`. (`docs/keep-awake.md`)

2. **الـping نفسه بيصرف حصة.** Render المجاني ٧٥٠ ساعة في الشهر
   للحساب كله، والخدمة النايمة مابتستهلكش. ping ٢٤ ساعة = ٩٩٪ من
   الحصة. (نفس الورقة)

3. **خانات الأرقام في الفورم `step="any"`.** البرنامج نفسه بيكتب فيها
   كسور (الملء من آخر زيارة بيجيب BMI ٢٧.٦٨ من القاعدة). وأي قيد خطوة
   بيخلي الخانة مرفوضة -- والمتصفح ساعتها **مابيبعتش حدث submit
   أصلاً**، فالزرار بيموت ساكت. (`tests/test_generate_button.py`)

4. **الحصص ليها سقف.** معامل التكبير بيضرب العدد زي الجرامات، فـ"بيض
   مسلوق ٣" بقت "بيض مسلوق ٧" على ورقة بنت ١٦ سنة. (`portion_scale.py`)

5. **البروتين بينضبط على نطاق السن والوزن.** جهاز التحليل بيقترح أرقام
   توصل ٣.٦ جم/كجم لمراهقة -- تلت أضعاف التوصية. (`protein_need.py`)

6. **مفيش بيانات عملاء في الريبو.** أي ورقة عميل تتحط كعيّنة لازم
   يتشال منها الاسم والرقم. وملف النسخة الاحتياطية (`backup.py`) فيه
   أسامي وتليفونات وأوزان كل العملاء -- مايترفعش ولا يتبعت.

7. **الورقة اللي بتتسلّم للعميل بسيطة بالقصد:** جدول + مسموح + ممنوع.
   الملاحظات الإكلينيكية بتظهر في المعاينة للدكتور، مش على ورقة
   العميل.

## الشكل العام

| | |
|---|---|
| `app.py` / `core.py` | التطبيق، القاعدة، الحارس، `/health` |
| `routes_*.py` | الصفحات: الخطط، الأدمن، الدفع، العام |
| `plan_engine.py` | توليد الأسبوع والورقة والـPDF |
| `booking.py` / `routes_booking.py` / `booking_notify.py` | حجز الاستشارة: المواعيد، الطلب، القبول والرفض، الدفع بالتحويل، الإشعارات والتذكيرات (`replica/architecture.md`) |
| `client_app.py` | يوميات العميل: المياه، ملاحظات الوجبات، التوصيات، تقييم الاستشارة، والشريط السفلي على الموبايل |
| `plan_tools.py` | فحص الخطة وهي بتتعدّل (مجموع اليوم + تصادم مع حالة العميل)، والقوالب |
| `equivalents.py` | بدائل الأصناف للعميل: نفس السعرات والماكروز، ومفلترة على حالته من قايمتين |
| `meal_database.py` / `meal_macros.py` / `food_data.py` | الأكل والماكروز |
| `protein_need.py` / `portion_scale.py` / `zigzag.py` | الحسابات الإكلينيكية |
| `lab_report.py` / `ocr_report.py` | قراءة ورق التحليل |
| `backup.py` | نسخة من القاعدة بزرار |
| `templates/` | الصفحات. `generate.html` أكبرها |
| `tests/` | اختبار لكل حاجة اتكسرت مرة، والسبب مكتوب في الـdocstring |

‏**التعليقات في الملفات دي مش شرح لـ"إيه" -- دي "ليه".** كل تعليق طويل
في الكود بيحكي حاجة حصلت فعلاً وكلّفت حاجة. ده أهم اللي في الريبو، مش
الكود نفسه.
